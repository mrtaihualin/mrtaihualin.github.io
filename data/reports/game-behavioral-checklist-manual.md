# Checklist มือ — พฤติกรรมยามเฝ้าประตูเกม (P3 · Lin ทดสอบเอง)

ต่อยอดจาก `data/game-content-tester.html` (ทดสอบเฉพาะเพดานเนื้อหา game-content ได้อัตโนมัติ)
รายการด้านล่างนี้ **ทดสอบอัตโนมัติแบบ static (อ่านโค้ด) ไม่ได้** เพราะต้องพึ่ง Supabase จริง
(ฐานข้อมูล/เวลาจริง/rate limit จริง) — Lin หรือผู้ตรวจต้องกดทดสอบเองตามขั้นตอนนี้

ตัวทดสอบ static ที่ตรวจแทนได้แล้ว: `node scripts/tests-game-behavioral.js`
(ตรวจว่าโค้ด "เรียกยามถูกจุด" — ไม่ได้พิสูจน์ว่ายามบน Supabase จริงทำงานถูก)

## 1) เพดานเล่นเกมเลโก้ต่อวัน (2 ประโยค/วัน ไม่ล็อกอิน · 5 ประโยค/วัน ล็อกอิน)

**เตรียม:** เปิด `lego.html` บนโดเมนจริง (mrtaihualin.com) ไม่ใช่ file://

| ขั้นตอน | คาดหวัง |
|---|---|
| ไม่ล็อกอิน กด "🧪測試" ครั้งที่ 1-2 | เริ่มทดสอบได้ปกติ |
| ไม่ล็อกอิน กด "🧪測試" ครั้งที่ 3 (วันเดียวกัน) | ขึ้นข้อความ "今天已經測試 2 句囉！" บล็อกไม่ให้เริ่ม |
| ล็อกอินแล้ว กด "🧪測試" ครั้งที่ 6 (วันเดียวกัน) | ขึ้นข้อความ "今天已經測試 5 句囉！" บล็อกไม่ให้เริ่ม |
| ล้าง localStorage / เปิด incognito แล้วลองใหม่ (ไม่ล็อกอิน) | โควตายังเดิม (นับที่ IP ฝั่งเซิร์ฟเวอร์ ไม่ใช่เบราว์เซอร์) — พิสูจน์ว่าเป็นเพดานแข็งจริง ไม่ใช่เพดานนุ่มแบบเก่า |
| ปิดเน็ต/บล็อก `lego-daily-limit` ผ่าน devtools แล้วกด "🧪測試" | ขึ้น "⚠️ 連線不穩，暫時無法測試" — **ห้ามให้เริ่มทดสอบได้** (fail-closed ตามที่ CLAUDE.md บันทึก) |
| กดปุ่ม "🧪測試" รัวๆ ติดกัน (double-click) | ต้องไม่นับโควตาเกิน 1 ครั้งต่อการกด 1 ครั้งจริง (กันเช็ค `legoQuotaCheckInFlight`) |

⚠️ ข้อจำกัดที่ต้องรู้ (บันทึกไว้ในโค้ดแล้ว): กันคนไม่ล็อกอินด้วย IP hash — สลับ WiFi→4G/เปิด VPN
จะได้โควตาใหม่ ไม่ใช่บั๊ก เป็นขีดจำกัดมาตรฐานของระบบไม่บังคับล็อกอิน

## 2) rate limit ของ `tone-round` (60 รอบ/นาที) — กันสคริปต์โกงดาวถี่ๆ

**เตรียม:** ล็อกอินแล้ว เปิดเกมที่เรียก `TONE_SERVER.finishRound()` (เช่น tone-finder.html)

| ขั้นตอน | คาดหวัง |
|---|---|
| เล่นเร็วมากติดกันเกิน 60 ครั้งภายใน 1 นาที (หรือยิง `TONE_SERVER.finishRound()` ผ่าน console วนลูป) | ครั้งที่เกินโดน 429 → toast "🌾 玩得太快啦！休息一下" ขึ้นจริง (ไม่ใช่ error เงียบ) |
| toast ขึ้นซ้ำในช่วง 10 วินาที | ต้องไม่เด้งซ้ำถี่ (กันแช่จอด้วย toast รัว — เช็ค `_rlToastAt`) |
| หลังโดน 429 เกมยังเล่นต่อได้ปกติ (แค่ไม่ได้บันทึกดาวรอบนั้น) | เกมไม่ค้าง/ไม่พัง |

---

## 3) SRS/ดาวต้องมาจากเซิร์ฟเวอร์เท่านั้น (offline-safe)

**เตรียม:** ล็อกอินแล้ว เล่นเกมที่มีดาว (เกมอ่าน/เกมพิมพ์/เกมเสียง/เกมลำดับคำ/เกมรวม)

| ขั้นตอน | คาดหวัง |
|---|---|
| ปิดเน็ต (หรือบล็อก `tone-round` ผ่าน devtools) แล้วตอบถูก | **ห้ามขึ้นว่า "ได้ดาว"** — คำนั้นต้องเล่นซ้ำได้รอบหน้า (ไม่เลื่อนขั้นปลอมฝั่ง client) |
| เปิดเน็ตกลับมาแล้วตอบถูกใหม่ | ได้ดาวจริง ขึ้นตรงกับที่เซิร์ฟเวอร์ตอบ |
| ไม่ล็อกอินเลย เล่นเกมเดียวกัน | ใช้ระบบดาว local เดิม (ไม่พึ่งเซิร์ฟเวอร์ — ตามที่ `tone-server.js` ออกแบบไว้ `available()`) |

## 4) เกมฟัง (listening-game) — ยืนยันกับ Lin ว่าไม่มีระบบดาว/SRS จริงๆ

ตัวทดสอบ static เจอว่า `listening-game-app.js` ไม่เรียก `TONE_SERVER.finishRound()` เลย
และไม่มีโค้ดให้ดาวฝั่ง client เองด้วย — ต่างจากอีก 5 เกมที่มี SRS ครบ

**ต้องถามให้ชัด:** เกมฟังตั้งใจไม่มีระบบดาว/SRS (เป็นเกมฝึกฟังอย่างเดียว) หรือเป็นงานที่ยังไม่ได้ทำ?
ถ้าตั้งใจ → บันทึกไว้ในเอกสารให้ชัดกันงงรอบหน้า ถ้าไม่ตั้งใจ → เปิดเป็นงานใหม่แยกต่างหาก
