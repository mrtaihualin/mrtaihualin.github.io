## โฟลเดอร์นี้คืออะไร

ที่เก็บ **"แบบแปลน" ของฐานข้อมูล** — บอกว่ามีตารางอะไร แต่ละตารางมีคอลัมน์อะไร มีด่านอะไรกันอยู่

เปรียบเทียบ: ถ้าฐานข้อมูลคือตู้เก็บเอกสาร โฟลเดอร์นี้คือ**แบบแปลนตู้** — บอกว่ามีกี่ลิ้นชัก ล็อกยังไง แต่**ไม่มีเอกสารข้างในตู้** (นั่นต้องพึ่งระบบสำรองข้อมูล ซึ่งเป็นคนละเรื่อง)

## ทำไมต้องมี

ตอนตรวจ `P2-03` เมื่อ 2026-08-07 พบว่า **21 จาก 37 ตาราง และ 34 จาก 41 ด่าน RLS ไม่มีไฟล์ต้นฉบับใน repo เลย** — รวมถึง:

- `classroom_students` (ข้อมูลนักเรียน ชื่อ LINE ID token)
- `classroom_payments` (ประวัติการจ่ายเงิน 20 คอลัมน์)
- `classroom_schedule` · `classroom_requests` · `classroom_recordings` และอีก 16 ตาราง

แปลว่า **ฐานข้อมูลหายแล้วสร้างโครงคืนไม่ได้** ต้องนั่งเดาโครงสร้างจากโค้ดเว็บทีละคอลัมน์ · และทำ staging/sandbox แยกก็ไม่ได้ (งาน `P7-01` ในแผนหลัก)

## ✅ ช่องโหว่ที่เคยมี — อุดแล้ว 2026-08-07 (บ่าย)

### ตัวนับเลขอัตโนมัติของ 9 ตาราง — อุดแล้ว

รอบแรกไฟล์ 01 เขียนแค่ `id bigint not null` ให้ 9 ตารางนี้ โดยไม่มีตัวนับเลขติดมาด้วย:

```
classroom_recording_issues · classroom_recordings · game_sentences · game_words
login_events · payout_ledger · reading_sessions · star_fraud_alerts · star_ledger
```

**สาเหตุ:** Postgres มี 2 วิธีทำเลขอัตโนมัติ — คำสั่งที่ใช้ดึงรอบแรกจับได้แค่วิธีเก่า (`nextval`) จับวิธีใหม่ (`generated as identity`) ไม่ได้

**อุดแล้ว** โดยรันคำสั่งอ่าน `pg_attribute.attidentity` เพิ่ม → ทั้ง 9 ตารางเป็น `generated always as identity` แล้ว

**เจอเพิ่มระหว่างอุด:** `game_reward_events.event_date` เป็น**คอลัมน์คำนวณ** (`generated always as (...) stored`) ไม่ใช่คอลัมน์ธรรมดาที่มีค่าเริ่มต้น — รอบแรกเขียนผิดเป็น `default` ซึ่งจะทำให้ index `uniq_daily_review` ทำงานผิดไปด้วย · แก้แล้วเช่นกัน

## ⚠️ ยังทำไม่เสร็จ

### 1. สิทธิ์ระดับตาราง (grant/revoke) เก็บไม่ครบ

จดไว้เป็นคอมเมนต์ในหัวข้อ `[99]` ของไฟล์ 01 เฉพาะ 3 ตารางที่ล็อก 2 ชั้น (`game_words`, `game_sentences`, `cron_state`) · ตารางที่เหลือใช้ค่าเริ่มต้นของ Supabase

### 2. ยังไม่มีระบบติดตามว่าไฟล์ไหนรันไปแล้ว

ตรวจแล้วพบว่าโครงการนี้ **ไม่มีระบบ migration เลย** — ยืนยัน 2 ชั้น: ตาราง `supabase_migrations.schema_migrations` ไม่มีอยู่จริง และรายชื่อ schema ทั้งหมดก็ไม่มี `supabase_migrations`

✅ **ปิดงานแล้ว 2026-08-07** — ตาราง `private.sql_run_log` (จากไฟล์ `supabase/sql/2026-08-07_migration_tracking.sql`) ยืนยันแล้วว่ามีอยู่จริง (Lin รัน `select to_regclass('private.sql_run_log');` ได้ผลกลับมา)

### 3. จุดสีแดง 3 จุดในฟังก์ชันที่เพิ่งกู้มา — ✅ แก้แล้ว 2026-08-07

`submit_payment_slip` · `delete_student_recording` · `get_game_link_status` เคยเป็น `SECURITY DEFINER` ที่คนไม่ล็อกอินเรียกได้โดยไม่มียามเฝ้าประตูเลย — แก้แล้วด้วย `supabase/sql/2026-08-07_add_guards_to_3_rpcs.sql` (Lin รันจริงแล้ว + ทดสอบใช้งานจริงผ่านครบ ดู `00_ศูนย์บัญชาการ_START-HERE.md`)

## สิ่งที่โฟลเดอร์นี้ **ไม่ได้** แก้

**ไม่ได้แก้เรื่องข้อมูลหาย** — ไฟล์พวกนี้สร้างได้แค่ "ตู้เปล่า" ข้อมูลนักเรียนกับประวัติการจ่ายเงินยังต้องพึ่งระบบสำรองข้อมูลแยกต่างหาก
(แพ็กเกจฟรีของ Supabase **ไม่มีสำรองอัตโนมัติเลย** และไม่มี PITR — เรื่องนี้แยกไปทำในแชทอื่นแล้ว ดู `21_ระบบสำรองข้อมูล.md`)
